# Podkop Rules

Независимые списки маршрутизации для Podkop **0.7.22**: Telegram, Twitch, Albion Online, Spotify и пользовательский набор KinoPub. Происхождение записей отмечено в реестре источников: официальные данные отделены от пользовательского ввода. Списки сообщества Podkop не используются. Проект готовит файлы, проверяет их и публикует через GitHub Raw; настройки роутера, VPN и sing-box не меняет.

Целевая инфраструктура пользователя: OpenWrt 25.12.5, VLESS Reality, sing-box. Пользователь подтвердил работу Albion через роутер с sing-box 1.12.17 после временного ограничения `hijack-dns` портом 53; одних списков для исправления оказалось недостаточно. Совместимость формата установлена по [коду Podkop 0.7.22](https://github.com/itdoginfo/podkop/tree/0.7.22), commit `c0a2736bb95884c19fedf638345ed6148c5fd6af`. [Результаты исследования](docs/podkop-compatibility.md).

В итоговом списке 37 CIDR с тем же множеством IP. **Среди них широкие сети, включая `57.0.0.0/8`; подключение `subnets/kinopub.txt` или `subnets/all.txt` направит через VPN также посторонний трафик.** [Происхождение, исключения и область действия](docs/kinopub.md).

## Формат и устройство проекта

Один ASCII-домен или IPv4 CIDR на строку; LF, завершающий перевод строки, сортировка, без комментариев и пустых строк. Полностью пустой файл допустим. Домен распространяется на себя и поддомены (`domain_suffix`), поэтому `telegram.org` включает `api.telegram.org` и `web.telegram.org`. Домены и подсети не смешиваются.

IPv6 в plain-text импорте Podkop 0.7.22 не поддерживается. Автообновление распознаёт IPv6 в источнике Telegram и отражает исключённые записи в отчёте; в публикуемые файлы они не попадают. Это не обеспечивает VPN-маршрутизацию IPv6.

```text
services.json                 единый реестр, enabled, auto_update, пути, source IDs
sources/sources.json          происхождение каждой записи и даты проверки
sources/manual/               сохранённые пользовательские входные данные
domains/, subnets/            сервисные файлы и сгенерированные all.txt
scripts/common.py             общая схема, форматы, источники, атомарная запись
scripts/build_lists.py        сборка all.txt по enabled
scripts/validate_lists.py     проверка схемы, происхождения и файлов
scripts/update_lists.py       безопасное обновление подтверждённых feed
tests/                        автономные unittest-тесты
docs/                         подключение, совместимость, диагностика, публикация
.github/workflows/            обновление и валидация
AGENTS.md                     постоянный процесс сопровождения через Codex
```

В `services.json` поле `domains` обязательно, а `subnets` указывается только при наличии запрошенного IP-списка. Для сервиса без IP-списка поле `subnets` отсутствует; пустой файл-заглушка не нужен. Сборка и проверка пропускают отсутствующий тип списка, автообновление не создаёт его. Источник типа `subnets` без зарегистрированного файла считается ошибкой. IP-список добавляется только по отдельному запросу пользователя. Общий `subnets/all.txt` формируется из существующих включённых IP-списков.

Общий модуль `common.py` добавлен для единых правил валидации во всех трёх скриптах. Внешних Python-зависимостей нет. Подсети не укрупняются: внутри сервисного файла пересечения отклоняются, а при сборке `subnets/all.txt` удаляются точные дубликаты и CIDR, полностью покрытые сетью другого включённого сервиса. Соседние сети не сливаются. Например, `/32` BattlEye сохранён в Albion, но в общем файле покрыт пользовательским `57.0.0.0/8` KinoPub. При отключении KinoPub точный `/32` автоматически возвращается в общую сборку. Равенство IP-покрытия проверяется тестом. Приватные/специальные диапазоны запрещены; префиксы шире `/16` запрещены по умолчанию. Для KinoPub задан список точных `broad_subnets` по прямому пользовательскому запросу с сохранённым исходным вводом. Произвольные широкие сети не разрешаются.

## Локальная работа

Нужен рабочий Python 3.12 или новее:

```sh
python -m pip install -r requirements.txt
python scripts/build_lists.py
python scripts/validate_lists.py
python -m unittest discover -s tests -v
python scripts/build_lists.py --check
python -m compileall -q scripts tests
```

Скрипты находят корень относительно своего расположения; для тестовой копии есть `--root PATH`. Сборка нормализует дубликаты в общих файлах; валидация дополнительно требует канонических сервисных файлов. Ошибки дают ненулевой exit code.

```sh
python scripts/update_lists.py --report update-report.json
```

Обновление: HTTPS с проверкой сертификатов, 20 секунд на попытку, до трёх попыток, ограничение ответа 1 MiB, проверка типа ответа, CIDR и общей сборки перед записью. HTML, пустой или повреждённый ответ сохраняют прошлую версию. Удаления из feed выводятся как `removal_candidates`, но не применяются автоматически. Новые подтверждённые CIDR добавляются; пересечения требуют ручного разбора. При ошибке одного сервиса остальные могут обновиться локально, но workflow не публикует изменения до успешной проверки всех источников.

`last_checked` — день успешной проверки источника (для автоматизации UTC); `last_updated` меняется при изменении набора маршрутов. Ручные даты обновляются только после фактической проверки. Повторный запуск с теми же данными в тот же день не меняет файлы и mtime. Новый день может изменить только дату проверки.

Для пользовательского ввода используются `trust: user-supplied`, `method: user-input` и `input_file` в `sources/manual/`. Если внешний источник отсутствует, `url: null`; независимая проверка не выполнена — `last_checked: null`. В этом случае `last_updated` отражает дату внесения пользовательских записей, а не подтверждение принадлежности адресов сервису.

Каждый файл заменяется атомарно через временный файл в той же папке и `os.replace`. Многофайловой транзакции на диске нет: при прерывании записи запустите build и validate перед публикацией. GitHub получает весь проверенный снимок одним commit.

## Автоматизация

`validate.yml` запускается на push, PR и вручную: компиляция Python, тесты, проверка реестра/источников/списков и актуальности `all.txt`. Разрешение только `contents: read`.

`update.yml` запускается ежедневно в 05:23 UTC (08:23 Москва) и вручную на основной ветке. Только эта задача имеет `contents: write`; commit/push происходят при наличии изменений и успешных проверках. Отчёт сохраняется artifact даже при ошибке. Секреты добавлять не требуется. При защите основной ветки, запрещающей push бота, потребуется публикация через PR с настройкой workflow владельцем. Автоматического обхода защиты нет.

Push через `GITHUB_TOKEN` не запускает обычный push-workflow повторно; поэтому тесты и валидация выполняются внутри update-job до commit. Это поведение описано в [документации GitHub](https://docs.github.com/en/actions/how-tos/write-workflows/choose-when-workflows-run/trigger-a-workflow). Расписание GitHub может задерживаться, а в неактивных публичных репозиториях отключаться.

## Добавление и сопровождение

Откройте репозиторий в Codex и напишите «Добавь Discord», «Обнови Telegram», «Проверь актуальность всех списков» либо «Удали Twitch». Порядок исследования, регистрации и проверки задан в [AGENTS.md](AGENTS.md).

При ручной работе: подтвердите официальные домены, API и CDN; добавьте `domains/<id>.txt`, источники с `records` и запись в `services.json`. Файл `subnets/<id>.txt` и поле `subnets` добавляйте только по отдельному запросу на IP-список и при наличии данных; пустые заглушки не создавайте. Пересоберите all.txt, запустите проверки, обновите таблицу и ограничения. Скрипты автоматически обнаруживают новый сервис по реестру. `enabled: false` исключает его из общих файлов. Без надёжного машинного источника ставьте `auto_update: false`.

## Ограничения

**Spotify:** три корневых домена покрывают web, авторизацию, API и поддомены CDN. IP-список содержит 12 точных `/32` из DNS-снимка узлов официального resolver; это динамические адреса, не полный перечень сетей или медиа Spotify. IP могут быть общими с другими приложениями; весь Google/CDN не включён. IPv6, внешние подкасты, дополнительные CDN и реальный маршрут не проверены. [Источники, границы и диагностика](docs/spotify.md).

**Telegram:** основной/API/web-трафик покрывается доменами, прямые MTProto-соединения — официальными CIDR. Дополнительные домены из `fdc5290` отмечены в источниках как пользовательские; их связь с сервисом независимо не подтверждена. Это относится к Desktop, Android, iOS и web при прохождении через роутер, но проверка клиентов не выполнялась. Медиа и файлы используют инфраструктуру Telegram; новые внешние зависимости требуют исследования. UDP, P2P-адреса собеседников и сторонние STUN/TURN не гарантируются списками. Нужна проверка поддержки UDP действующим VPN; конфигурацию проект не меняет.

**Twitch:** `twitch.tv` покрывает сайт, API, авторизацию, чат и часть VOD; `ttvnw.net` — доставку видео, `jtvnw.net` и `twitchcdn.net` — ресурсы/CDN. В `fdc5290` добавлены `ext-twitch.tv` и `twitchsvc.net`; их происхождение оформлено как пользовательское, независимая проверка не выполнена. При смене CDN возможны дополнительные конкретные домены CloudFront: добавляйте только после проверки HAR. Сам список Twitch не включает целые сети AWS/Fastly и корень `cloudfront.net`; общий список подсетей теперь включает широкие пользовательские маршруты KinoPub. Нет заявления о полном покрытии всех VOD/расширений.

**KinoPub:** все присланные домены и IP сохранены с удалением только избыточных вложенных CIDR. Это вручную сопровождаемый пользовательский набор, а не официальный feed. Общие CDN, TMDB и `wp.com` могут затрагивать другие приложения. Адреса, транспорты и полнота покрытия на реальном клиенте не проверялись. [Подробности](docs/kinopub.md).

**Albion Online:** включены сайт и подтверждённые DNS-имена входа Americas/Asia/Europe. По пользовательским захватам добавлены точные адреса статуса трёх регионов, CNAME входа Europe и домены BattlEye/CDN. По отдельному запросу создан `subnets/albion.txt`: 17 наблюдаемых IPv4 `/32`, включая DNS-наблюдения игровых узлов Europe, статусов, сайта/CDN и BattlEye. Дополнения отмечены как `user-supplied`; часть IP видна только в DNS, принадлежность исключительно игре и стабильность адресов не подтверждены. Полного перечня игровых IP всех регионов нет. Обновление списков не исправило вход через роутер; пользователь подтвердил, что временное добавление `port: 53` к правилу `hijack-dns` позволило Albion заработать. Правка конфигурации находится вне механизма списков и может исчезнуть при регенерации конфигурации Podkop. [Результаты теста](docs/albion-capture-results.md), [инструкция анализа](docs/albion-network-analysis.md).

Зашифрованный DNS клиента, кэш DNS, прямой IP, IPv6 и сторонние прокси могут менять результат доменных правил. Работа VPN и задержки зависят от транспорта и маршрута; списки этого не исправляют. [Диагностика](docs/troubleshooting.md).

## Публикация и проверки

В Git настроен `origin` на `https://github.com/RedHeadDamien/podkop-rules.git`. Статус серверных GitHub Actions и доступность Raw URL при этом обновлении README не проверялись. Инструкции публикации и проверки ссылок приведены в [docs/publishing.md](docs/publishing.md); при уже настроенном `origin` используйте существующий репозиторий, а не команду его повторного создания.

Проверки после добавления Spotify, KinoPub и исторические результаты первоначальной версии находятся в [docs/verification.md](docs/verification.md). Успешная локальная валидация пользовательского списка не означает независимого подтверждения принадлежности его адресов сервису.

Лицензия MIT относится к коду и документации проекта; первичные источники сохраняют свои права. Это независимый проект, не официальный продукт Podkop, Telegram, Twitch или Sandbox Interactive.
