# Albion Online: анализ реальных соединений

Списки охватывают сайт и три подтверждённых DNS-имени входа. В [ответе разработчика](https://forum.albiononline.com/index.php/Thread/198781-server-ip-address/) указаны диагностические адреса:

| Регион | DNS-имя |
|---|---|
| Americas | `loginserver.live.albion.zone` |
| Asia | `live02-loginserver.sg.albion.zone` |
| Europe | `live03-loginserver.ams.albion.zone` |

Это не полный перечень IP игровых сессий. [Заявление разработчиков о сети](https://forum.albiononline.com/index.php/Thread/221517-Understanding-Albion-Online-Connection-Issues/) описывает единый мир на регион и глобальный слой DDoS-защиты: точка входа зависит от маршрута и может меняться. Подтверждённый актуальный CIDR-feed не найден. Полный перечень TCP/UDP-портов официальными материалами не установлен; не используйте предполагаемые порты как доказательство.

## Подготовка Windows 11

Закройте фоновые загрузки и браузеры. Зафиксируйте время, регион, версию клиента, адрес Windows в LAN и этап: launcher, загрузка обновлений, вход, выбор персонажа, игра, переход между зонами. Повторите минимум два раза для каждого нужного региона. Пассивный захват не требует сканирования чужих серверов.

### Resource Monitor и TCPView

Откройте `resmon.exe`, вкладку «Сеть», выберите процесс клиента по фактическому имени и пути. Наблюдайте «Сетевая активность» и «TCP-подключения». Отделите launcher от игрового клиента: у них могут быть разные PID. Resource Monitor не даёт полного перечня удалённых UDP-партнёров.

[TCPView Microsoft Sysinternals](https://learn.microsoft.com/en-us/sysinternals/downloads/tcpview) показывает владельца локальных endpoints. Отключение разрешения имён помогает увидеть числовые IP. Для UDP инструмент может показывать только локальный endpoint; удалённый адрес определяйте захватом пакетов. PID может переиспользоваться, поэтому фиксируйте время и путь процесса.

### PowerShell

```powershell
Get-Process | Where-Object ProcessName -Match 'Albion|Launcher' | Select-Object Id, ProcessName, Path
$albionPid = 1234 # замените фактическим PID игрового клиента
Get-NetTCPConnection -OwningProcess $albionPid | Select-Object LocalAddress, LocalPort, RemoteAddress, RemotePort, State
Get-NetUDPEndpoint -OwningProcess $albionPid | Select-Object LocalAddress, LocalPort
Resolve-DnsName loginserver.live.albion.zone -Type A
Resolve-DnsName live02-loginserver.sg.albion.zone -Type A
Resolve-DnsName live03-loginserver.ams.albion.zone -Type A
```

В PowerShell не используйте `$PID` для своего значения: это системная переменная. `Get-NetUDPEndpoint` не раскрывает удалённый UDP-адрес. DNS-ответ — кандидат для сравнения, не доказательство игрового IP. Если DNS обслуживается Podkop, ответ может быть FakeIP.

### Wireshark

Выберите активный Ethernet/Wi-Fi-интерфейс. Запустите короткий захват до запуска клиента, остановите после входа и смены зоны. Display filter для клиента `ip.addr == 192.168.1.100` замените своим LAN-адресом; для UDP используйте `udp`, для DNS — `dns`, для видимого TLS SNI — `tls.handshake.extensions_server_name`. Не делайте выводов по отсутствию SNI: ECH/шифрование и прямые IP скрывают доменное имя.

Сопоставляйте локальный UDP-порт с `Get-NetUDPEndpoint` и временем жизни PID. В Statistics → Conversations изучите endpoints, объём, длительность и активность при движении/переходе зоны. Wireshark обычно не знает Windows PID: корреляцию делайте по порту и времени. Отдельно отмечайте TCP launcher/CDN, авторизацию и длительные игровые UDP-потоки. Захваты не публикуйте: они могут содержать приватные данные.

## OpenWrt

Если tcpdump уже установлен, пользователь может выполнить:

```sh
ip -br link
tcpdump -ni br-lan -s 128 -c 3000 -w /tmp/albion-lan.pcap 'host 192.168.1.100 and (tcp or udp)'
```

Замените LAN-интерфейс и адрес ПК фактическими. Захват ограничен 3000 пакетами, его можно остановить Ctrl+C; используйте `/tmp` с учётом свободной RAM. Если tcpdump отсутствует, установка — отдельное решение пользователя. Откройте pcap локально в Wireshark.

LAN-захват показывает исходные endpoints или FakeIP. После TPROXY/NAT WAN может показывать только VPN-сервер; сопоставляйте направление, порты и время, не считайте IP VPN адресом Albion. Не меняйте nftables и VPN для получения трассы. IPv6 анализируйте отдельно: проект публикует только IPv4.

## Решение о добавлении адреса

1. Повторите наблюдение на одном регионе в разные дни, включая вход и переходы зон. Зафиксируйте реальные назначения и транспорт.
2. Сопоставьте пакеты с процессом, DNS, SNI (если доступен) и временем игровой активности. Фоновый launcher, браузер, обновления Windows и CDN исключайте по этим признакам.
3. Проверьте RDAP/WHOIS и сведения провайдера как дополнительный контекст. ASN и обратный DNS не доказывают исключительное использование Albion.
4. До публичного включения нужны независимые подтверждения назначения и актуальности. Отдельный наблюдаемый IP при достаточном подтверждении добавляют как `/32`, а не сеть провайдера. Нельзя расширять диапазон из-за соседних адресов.
5. Запишите источник, дату, регион, транспорт, этап игры и границы уверенности в источники/документацию. Публичные отчёты обезличивайте. Неподтверждённые кандидаты оставляйте только в описании, вне маршрутизируемых списков.
6. После изменения пересоберите all.txt, запустите тесты и validate. При смене DDoS-провайдера/адресов повторите анализ; удаление старого маршрута требует доказательства устаревания.

Одна успешная авторизация не подтверждает работоспособность всей игры через VPN. Все три региона требуют отдельных тестовых сеансов. Пока таких наблюдений нет, `subnets/albion.txt` остаётся пустым, а полное игровое покрытие не заявляется.
