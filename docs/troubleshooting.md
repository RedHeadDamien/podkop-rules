# Диагностика

Команды ниже пользователь выполняет на OpenWrt. Сначала соберите сведения, не меняя конфигурацию. Не публикуйте приватный UCI-конфиг, VLESS-ссылки, токены, журнал авторизации или полный захват трафика.

## DNS и доступность Raw

```sh
date
nslookup raw.githubusercontent.com
nslookup web.telegram.org 127.0.0.1
nslookup www.twitch.tv 127.0.0.1
nslookup live03-loginserver.ams.albion.zone 127.0.0.1
curl -fL --connect-timeout 10 --max-time 30 https://raw.githubusercontent.com/OWNER/podkop-rules/main/domains/all.txt
```

Проверьте правильность `OWNER`/ветки, HTTP-статус и содержимое. Если `curl` отсутствует, используйте установленный `wget -O /tmp/podkop-domains-check.txt URL` и изучите файл; не исполняйте его. HTTP 404/HTML не являются списком. Убедитесь, что часы верны для TLS. Не отключайте проверку сертификатов.

Сравните DNS-запрос клиента с запросом к роутеру. Внешний DoH/DoT приложения, DNS-кэш и AAAA могут менять путь. FakeIP в ответе Podkop — нормальное поведение для соответствующего доменного правила; его нельзя публиковать как адрес сервера. Запрос к публичному DNS показывает другую картину и не доказывает маршрут клиента.

## Состояние служб и обновлений

```sh
ubus call service list '{"name":"podkop"}'
ubus call service list '{"name":"sing-box"}'
logread | grep -Ei 'podkop|sing-box' | tail -n 100
crontab -l | grep podkop
uci -q get podkop.settings.update_interval
```

Логи `Download ... failed` проверяйте отдельно от доступности сайта. Пустые файлы подсетей Twitch/Albion не подключаются. После самостоятельного применения настроек пользователь при необходимости может вызвать `podkop list_update`; автоматического запуска этой команды проект не делает. Не перезапускайте все службы до сохранения сведений о проблеме.

## Маршрутизация и VPN

```sh
nft list tables
nft list ruleset
ip -4 rule show
ip -4 route show table all
ss -lntu
```

Изучите таблицу Podkop и IPv4-набор `podkop_subnets`; конкретное имя таблицы смотрите в `nft list tables`. Для Telegram ожидаются CIDR из `subnets/telegram.txt`. Доменное правило при прямом IP может не сработать. Проверьте доступность уже настроенного VPN средствами его текущей диагностики, не публикуя адреса/ключи. Рабочая HTTPS-страница через VPN не доказывает поддержку UDP.

Не подставляйте выдуманный путь конфига sing-box в `sing-box check`. Если конфиг известен и доступен, `sing-box check -c <actual-path>` проверяет его синтаксис, но не сетевую доступность. Полный конфиг может содержать секреты.

## UDP, звонки и игры

Сравните TCP и UDP одного тестового сеанса. В Telegram звонок может идти через P2P-адрес собеседника вне официальных подсетей. У Albion логин и игровая сессия могут иметь разные адреса. Изучайте таблицу соединений и ограниченный захват на LAN/WAN; для игрового анализа см. [отдельную инструкцию](albion-network-analysis.md).

Проверьте потери, MTU и задержки на имеющемся VPN отдельно. Номер порта сам по себе не подтверждает приложение. ICMP может блокироваться; отсутствие ping не означает недоступность игры. При IPv6 доменная/IPv4-проверка не гарантирует отсутствие обхода VPN по AAAA.

## Ошибки проекта

`python scripts/validate_lists.py` объясняет некорректную строку/реестр/источник. Для устаревшего `all.txt` выполните build, затем validate. Если в отчёте `kept-last-good`, источник не обновлён; прошлые записи сохранены. `removal_candidates` требуют ручного подтверждения устаревания. Источники и даты находятся в `sources/sources.json`.
