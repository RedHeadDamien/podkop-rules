# KinoPub: пользовательские списки

Добавлены по явному запросу пользователя 11 ноября 2026 года. Идентификатор сервиса — `kinopub`, сопровождение ручное (`auto_update: false`).

| Файл | Количество |
|---|---:|
| `domains/kinopub.txt` | 29 доменов |
| `subnets/kinopub.txt` | 37 IPv4 CIDR |
| Исходный пользовательский ввод | 29 доменов и 52 CIDR |

## Происхождение

Исходные записи сохранены в [sources/manual/kinopub.json](../sources/manual/kinopub.json), метаданные — в [sources/sources.json](../sources/sources.json). Уровень доверия `user-supplied`, метод `user-input`, внешняя URL-ссылка отсутствует (`url: null`), дата независимой успешной проверки не установлена (`last_checked: null`). Это пользовательский набор маршрутов, а не подтверждённый официальный перечень инфраструктуры KinoPub.

Официальный сайт `https://kino.pub/` при исследовании через веб-инструмент вернул HTTP 502; это не доказывает ни исправность, ни неисправность остальных доменов. Все присланные домены сохранены. Убраны завершающие `\`, `gfw\.ovh` преобразован в `gfw.ovh`; пути и регулярные выражения в публикуемые файлы не попадают.

Из 52 исходных CIDR удалены только 15 сетей, уже полностью входящих в другой присланный CIDR. Например, `31.40.217.114/32` покрывается `31.40.217.0/24`, а `104.21.62.0/24` — `104.16.0.0/12`. Ничего не укрупнялось: объединённое множество IP до и после обработки совпадает, что проверяется автоматическим тестом. Перечень удалённых вложенных записей есть в исходном JSON.

## Область действия

Следующие префиксы шире `/16` включены как **точные исключения по прямому запросу пользователя**, перечисленные в `services.json` → `kinopub.broad_subnets`:

```text
104.16.0.0/12
13.32.0.0/12
15.236.0.0/14
172.64.0.0/13
35.176.0.0/13
44.192.0.0/10
52.0.0.0/10
57.0.0.0/8
8.32.0.0/11
```

Они направят через VPN весь совпавший трафик, включая другие сайты и приложения. Например, `57.0.0.0/8` охватывает 16 777 216 IPv4-адресов. Эти сети не объявляются выделенными или принадлежащими исключительно KinoPub. Домен `wp.com`, а также TMDB-домены тоже затрагивают общие внешние зависимости.

[Официальный перечень Cloudflare](https://www.cloudflare.com/ips-v4/) содержит общие сети провайдера, в том числе `172.64.0.0/13`. Сам факт использования общего CDN не доказывает необходимость маршрутизации всей сети для KinoPub. В пользовательском вводе `104.16.0.0/12` также шире опубликованных Cloudflare `104.16.0.0/13` и `104.24.0.0/14` вместе. Исходный диапазон сохранён по запросу, не выдан за официальный feed.

Без конкретного исключения валидатор продолжает запрещать префиксы шире `/16`. Исключения не отключают проверку специальных/приватных сетей, IPv6, пересечений и точного происхождения записей. Автоматические feed не получают разрешение добавлять широкие префиксы.

## Подключение

В «Внешние списки доменов»:

```text
https://raw.githubusercontent.com/RedHeadDamien/podkop-rules/main/domains/kinopub.txt
```

В «Внешние списки подсетей»:

```text
https://raw.githubusercontent.com/RedHeadDamien/podkop-rules/main/subnets/kinopub.txt
```

Эти файлы также входят в `domains/all.txt` и `subnets/all.txt`, поскольку сервис включён. Не подключайте одновременно all.txt и те же сервисные файлы без необходимости. Ссылки на новые файлы начнут отдавать данные после commit/push; публикация и проверка на роутере в рамках этого изменения не выполнялись.
